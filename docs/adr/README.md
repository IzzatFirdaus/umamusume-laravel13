# ADR index

## Errata convention

A dated document claim that later proves wrong is corrected by appending a dated line to the ADR's
`## Ledger`, which preserves the original sentence verbatim and states which part of the claim still
holds. The point is not archival politeness: an ADR's status line and its consequence list are what later
sessions read *instead of* re-deriving the decision, so a silent rewrite destroys the only record that
the reasoning ever existed.

The mechanism changed on 2026-10-12. Appending an erratum to the top of a file raised its length
monotonically and buried history in the most-read location — `ADR-0008` carried four corrections and a
95-line preamble, 24% of its own file, before its Decision began. So the record is now split in three:

| Thing | Lives in | Changes |
|---|---|---|
| The ruling | the ADR body | never |
| What has happened since | the ADR's `## Ledger` | append-only, newest first |
| What is true right now | `CURRENT.md` + the index below | regenerated |

`ADR-0008` established the form and `ADR-0012` numbered its errata. `ADR-0015` is now the clearest case
for it: its first consequence asserted that the bound a Trainer sees as a bar end is the bound the form
enforces, and that was false on one branch for a day. Deleting the claim would have destroyed the
evidence that a reasonable author believed it, which is what a reader needs in order to trust the
correction.

**The rule that came out of that erratum, promoted because it generalises beyond the one bug: unifying
the function is not unifying the call. Where one number is read by a validator and a renderer, the
record must say which *argument* both pass, not only which helper both call.** `ADR-0015` moved both
readers onto `ScenarioCaps` and stopped there, so the disagreement survived *inside* the single owner —
the validator passed `forRun($run)`, the band's caller passed `scenarioKey()`, and the ADR still read as
though it had succeeded. The same shape produced three findings in the pass that fixed it: `AGENTS.md`
citing an `FR-x` notation the PRD does not use, `PRD.md` not citing three shipped columns, and two
architecture listings omitting fields their own table has. Each is two sides believing they pointed at
the same fact.

## The contract

Every ADR carries one `ADR-CONTRACT` HTML comment directly under its H1, and the index below is
generated from it. See `ADR-TEMPLATE.md` for the field list, the body caps and the reciprocal rule
(a relation visible from one file must be visible from the other).

## Read order

1. **`CURRENT.md`** — one row per current fact, grouped by topic, including the negative rows ("do not
   do X"). This is the file that replaces re-deriving state from 25 bodies.
2. **The index below** — one row per ADR, with its decision, its code state, its relations and what is
   still open.
3. **The one or two ADR bodies the row points at.** A session that reads all 25 has paid for state the
   index should have given it.

Regenerate the index with:

```bash
python3 tools/adr-index.py docs/adr --write
```

Guard the set with:

```bash
python3 tools/adr-check.py docs/adr      # also `composer docs-adr`
```

`adr-check.py` reports the failure modes that made this directory expensive to read: an ADR on disk with
no index row, an authority relation visible from one file and not the other, a data row typed into more
than one ADR, a table interrupted mid-body, preamble bloat and an over-long Decision.
