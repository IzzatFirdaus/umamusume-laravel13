What inheritance actually does

MechanismEffectSource
Blue spark Raises a stat's cap by +16 per ★3 basic-ability factor, applied at run start, at the Classic inheritance moment and at the Senior one. §1.3.4
Pink spark Shifts an aptitude grade. Measured values are +5 / +12 / +21 per stat by grade. §1.5.1–1.5.3
Unique-skill factor Raises caps in proportion to the donor's growth rates. §1.3.4
Enhanced spark Carries a stat bonus and a skill hint into inheritance. Only reachable from a won powered-up duel or an event, and its trigger rate is unpublished. §2.2.1

○ The cap raise is the loop. Train to a final total, bank the factor grade, inherit the +16 per ★3, then train past the previous ceiling (UMAMUSUME_REFERENCE.md §1.3.6). A run with two ★3 blue parents therefore starts with a higher ceiling than the scenario publishes, which is why the cockpit shows an entered ceiling beside the scenario's rather than one number.

Parents must differ

A veteran cannot be its own parent, and the two slots cannot hold the same record. The picker enforces the first rule by hiding the trainee you are running; the second by disabling an already-chosen record.

○ Choosing no parents is a legitimate build, not an error. The run record carries two nullable parent ids for exactly that reason, and no screen invents a default pair.

Annotation key · Legacy selection

  1. The mechanism is explained where the choice is made. Inheritance is the least obvious system in the game and the one most likely to be misread as decoration. Putting the +16-per-★3 rule on the selection screen answers it before a Trainer has to ask (Paradox of the Active User).
  2. A projected start table, not a promise. One row moves because one parent was chosen; the other four stay at the scenario cap. The table shows the arithmetic's effect rather than a "power score".
  3. Empty is a valid state, shown as one. "Leave empty" is an outline button beside the primary, and the note says a parentless build is legitimate. That is the Difference between an absence and an error.
  4. Enhanced sparks are described but never given a rate. The trigger rate is published nowhere; the row says so instead of implying a probability.
  5. Two slots, two cards, one chosen. The chosen parent takes the pick border and the positive pill; the empty slot stays neutral. Same selection grammar as the scenario and trainee steps.
  6. Heuristic coverage. H10. Each slot states what it needs and the screen says what happens if it is left empty, so the rule arrives at the point of use.
  7. Framework coverage. Information architecture 1 on objects. The unit is the pair, because the sparks combine, so a saved legacy is one object and not two records that happen to be adjacent.
  9. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is in the top bar because the bar is the one row present at every width. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
  11. The type is a chip, and the chip is never the mark alone. The client identifies a support card by the chip it wears, so the type column carries the client's own glyphs in the client's own chip colours. The word stays beside the mark, because a mark alone breaks WCAG 1.4.1 and because a stat carries no saturated identity hue (DESIGN-CORPUS.md:371-393): the identity is the glyph plus a whisper of band tint, and the hue is spent on meaning.
