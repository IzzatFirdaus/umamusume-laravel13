Annotation key · 419

  1. It answers the data-loss question first. "Your last saved turn is unaffected" is the first sentence, because it is the only thing a Trainer cares about at this moment.
  2. It distinguishes saved from unsaved. The table names what survives and what does not, instead of a generic "try again".
  3. It does not auto-retry. Automatically resubmitting a stale form can duplicate a turn; asking a human to reload is the safe path.
  4. One error surface. The page replaces the framework's modal rather than stacking on top of it.
  5. Peak-End: the first sentence answers the question the reader actually has. "Your last saved turn is unaffected" precedes any explanation of the expiry, because a 419 is read as data loss until it is not.
  6. Heuristic coverage. H9. The data-loss question is answered in the first sentence, so recovery starts from what is still intact.
  7. Framework coverage. Shneiderman 5 on error prevention and Tognazzini 13 on protecting the user's work. The data-loss question is answered in the first sentence, and the entered state is not destroyed by the failure.
  9. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is in the top bar because the bar is the one row present at every width. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
