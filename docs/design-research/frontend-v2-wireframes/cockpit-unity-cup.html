Annotation key · Cockpit

  1. One decision, stated once. The recommendation, its reason and its cost all live in one block. The shell's page-head carries the same action as the single primary, so a Trainer can act without scrolling.
  2. The finale countdown is in the scenario card, not only in the advisor's why-list. In the running app it appears only as one bullet below the fold, which is the Goal-Gradient failure the audit filed.
  3. Stat bars use the entered ceiling. 1325 / 1322 / 1368 / 1308 are this run's own, and the scenario's published 1300 is not printed as if it were the same fact.
  4. The two full treatments exist. This page is the shell-density view; the twelve-change version with token mapping is cockpit-wireframes-2026-10-21/05-unity-cup-hfw-v2.html.
  5. Heuristic coverage. H1. Energy band, mood tier, burst count and the finale countdown are all system status, printed rather than implied.
  6. Framework coverage. Gerhardt-Powals 3 on fusing data and Information architecture 7 on focused navigation. The resource strip fuses turn, energy, fans and the next obligation into one reading, and the rail stays banded rather than growing with the run.
  8. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is at the head of the rail, where DESIGN.md §2.2 puts a control that belongs to a pane: the penalty for a distant control is exactly why the top-bar version was wrong. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
