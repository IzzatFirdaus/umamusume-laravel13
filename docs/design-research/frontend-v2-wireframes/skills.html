Annotation key · Skills

  1. The engine condition is shown in monospace beside the readable name. This is the "raw engine data shown as-is with a note" pattern the HLF proved is safest to adopt: a Trainer who understands the flags gets them, and one who does not reads the plain description.
  2. Cost here is the base. The hint discount belongs to the run's own planner, because a hint is per-run. Mixing the two would print a price the catalogue cannot know.
  3. Search covers name and effect text. Searching skill text is the common case — a Trainer remembers "last spurt", not the skill's name.
  4. Type is a filter, not a colour. Skills carry no saturated identity colour in this system, matching the per-stat whisper tints the token set already defines.
  5. Hick’s Law governs the filter set, not the result set. 1,910 records is not a list anyone reads, so the screen offers the deciding dimensions and keeps the engine condition in monospace beside the readable name. The raw value is shown rather than summarised away.
  6. Heuristic coverage. H8. Filters carry the deciding dimensions and the engine condition sits in monospace beside the readable name, with nothing decorative between them.
  7. Framework coverage. Information architecture 6 on multiple classification, and Information architecture 3 on disclosure. The filters carry the deciding dimensions and the engine condition sits in monospace beside the readable name.
  9. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is in the top bar because the bar is the one row present at every width. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
  11. The way back to the hub is a strip, not a word in a corner. The breadcrumb linked "Database", but it sits in the top bar on the brand-blue chrome with no underline, so it read as a word rather than as a link and a Trainer looking for the way back found the global rail instead. The nine areas are one family, so they are grouped as one family: a sub-navigation strip of the nine, with the current one marked, and the breadcrumb link now visibly a link. Information Architecture principle 7 (focused navigation) and principle 5 (front doors).
  13. The type is a chip, and the chip is never the mark alone. The client identifies a support card by the chip it wears, so the type column carries the client's own glyphs in the client's own chip colours. The word stays beside the mark, because a mark alone breaks WCAG 1.4.1 and because a stat carries no saturated identity hue (DESIGN-CORPUS.md:371-393): the identity is the glyph plus a whisper of band tint, and the hue is spent on meaning.
