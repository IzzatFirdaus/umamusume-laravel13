Annotation key · Import preview

  1. Every field is an edit box with a found / missing tag. The import is reviewable field by field rather than as an all-or-nothing commit, which is the preview-before-commit pattern the corpus declares.
  2. Missing fields say what to do, not just that they are empty. "Choose Active, Completed or Retired" names the valid set; an empty box with "required" is a puzzle.
  3. The one-turn-entry consequence is stated before the commit. This is the honest answer to the dashboard/cockpit turn disagreement found in the audit: an import records a position, so the strip's turn count and the cockpit's next turn can legitimately differ, and the importer says so rather than hiding it.
  4. Three counts at the top. Found, missing and source, so a Trainer knows at a glance how much work remains.
  5. Commit is the only filled action, and it names what it does. "Import this run", not "Continue".
  6. Law of Proximity keeps each qualifier beside its value. Every parsed value sits in an edit box with its own found or missing tag, so a Trainer checks the parse rather than remembering what they pasted. A single "4 missing" summary at the top would satisfy the count and not this law, because the reader would still have to hunt for which four.
  7. Heuristic coverage. H9. Each field shows what the parser found and what to do about a miss, so a bad parse is diagnosable rather than merely rejected.
  8. Framework coverage. WCAG 3.3.7 on redundant entry, and Norman on signifiers. Every parsed value is in an edit box with its own found or missing tag, so the Trainer checks a parse rather than retyping what they pasted.
  10. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is at the head of the rail, where DESIGN.md §2.2 puts a control that belongs to a pane: the penalty for a distant control is exactly why the top-bar version was wrong. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
