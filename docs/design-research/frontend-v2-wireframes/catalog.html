Annotation key · Umamusume catalog

  1. Cards, not a table. A trainee is identified by name and three aptitude letters, so a card grid reads faster than a nine-column table at this catalogue size. Above roughly 200 rows with more columns, the pattern inverts back to a table.
  2. Three letters, not nine. Each card shows the strongest value per axis; the detail screen owns the full set. That is the chunking the trainee picker also uses, so the grammar is learned once.
  3. The card names the debut form and its own rarity, because the two are not the same figure. Gold Ship's debut form is [Red Strife], an SR, and her second form is an SSR, so a card that printed one "trainee rarity" would be wrong for one of her two forms. The form count beside it is the number of forms the catalogue holds for her, and this screen's 67 trainees and 106 forms are that join.
  4. The growth row is on the card, and a zero is a real figure. The card prints the stats with growth because that is what decides a build; a stat it does not name has zero growth, and the detail screen prints all five cells at +0%, which is how the client prints them (UMAMUSUME_REFERENCE §1.3.5). All six cards here sum to 30 points, in five-point steps across one to four stats: Agnes Digital's four-stat row is the case that rules out a two-stat card.
  5. Aptitude never shares a label with a stat grade. The cockpit's stat-grade banding is marked provisional in config; this screen prints aptitudes only, and the lede says so.
  6. Release status is a word. "Global" is a pill with text. The catalog's JP-only case is rendered as a muted label in the running app, and no badge is invented here.
  7. Hick’s Law sets the filter count, not the row count. 67 trainees is long past the point where scanning beats choosing, so the deciding dimensions are filters and the results are cards. A table would add columns without reducing the number of decisions per trainee.
  8. Heuristic coverage. H8. Cards carry name plus three aptitude letters; every further column is behind the detail page, because it does not decide which trainee to open.
  9. Framework coverage. Information architecture 3 on disclosure and 2 on choices. A trainee is identified by name and three aptitude letters, so the card grid reads faster than a table and every further column is behind the detail page.
  11. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is at the head of the rail, where DESIGN.md §2.2 puts a control that belongs to a pane: the penalty for a distant control is exactly why the top-bar version was wrong. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
  13. The way back to the hub is a strip, not a word in a corner. The breadcrumb linked "Database", but it sits in the top bar on the brand-blue chrome with no underline, so it read as a word rather than as a link and a Trainer looking for the way back found the global rail instead. The nine areas are one family, so they are grouped as one family: a sub-navigation strip of the nine, with the current one marked, and the breadcrumb link now visibly a link. Information Architecture principle 7 (focused navigation) and principle 5 (front doors).
  14. The picture slots are drawings, and absence is a normal state. The app renders a mirrored card_portrait beside each trainee row at 48px (TraineeCatalog.vue, DESIGN.md §4.7). A file the mirror does not hold renders nothing — no grey box, no placeholder glyph — and the row keeps its name. The dashed frames here mark cells the picture would occupy, and the subject inside each names the picture that belongs there.
  15. These six are the catalogue's rows, not illustrations. Names, Japanese names, form titles, rarities, aptitude letters and growth figures are read from assets/data/umamusume.js, which the generator builds from the app's own tables. The catalogue holds 67 trainees and 106 forms; the running app's counter reads 71 because the dev database also holds four trainees a test wrote against a .test host, which this catalogue excludes.
