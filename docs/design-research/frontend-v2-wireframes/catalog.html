Annotation key · Umamusume catalog

  1. Cards, not a table. A trainee is identified by name and three aptitude letters, so a card grid reads faster than a nine-column table at this catalogue size. Above roughly 200 rows with more columns, the pattern inverts back to a table.
  2. Three letters, not nine. Each card shows the strongest value per axis; the detail screen owns the full set. That is the chunking the trainee picker also uses, so the grammar is learned once.
  3. Aptitude never shares a label with a stat grade. The cockpit's stat-grade banding is marked provisional in config; this screen prints aptitudes only, and the lede says so.
  4. Release status is a word. "Global" is a pill with text. The catalog's JP-only case is rendered as a muted label in the running app, and no badge is invented here.
  5. Hick’s Law sets the filter count, not the row count. 71 trainees is long past the point where scanning beats choosing, so the deciding dimensions are filters and the results are cards. A table would add columns without reducing the number of decisions per trainee.
