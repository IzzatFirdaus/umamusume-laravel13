Annotation key · Dashboard

  1. One primary action. "Open cockpit" is the only filled button in the top region. The page-head "New career" is the second, and only because a landing screen owes a way to start one; every other action is an outline or a link.
  2. Contradiction printed, not hidden. This screen reports turn 1 because stripValues() returns turnEntries->count(), while the cockpit reports turn 67 from nextTurnToPlay(). Both are labelled and the note names the defect. A wireframe that silently picked one would be the same class of error the audit filed against Energy.
  3. Absence keeps its tile. Energy and team rank say "not recorded" rather than dropping the row. The external prototype review's "drop the row" rule is applied to explanation paragraphs, not to a value the screen claims to report.
  4. Nav taxonomy, two levels. Ten destinations grouped as Play / My data / Library / System. The running sidebar is one flat list of ten, which breaches the "at or under eight" target recorded in AppLayout.vue:178; grouping fixes it without deleting a destination.
  5. Mobile is a different shape. Below 760px the sidebar becomes design-2.0 §41's bottom bar: Home / Career / Legacy / Deck / More.
  6. Accent discipline. The status lime appears once (the "1 active career" pill), the action blue once (the primary), the risk red once (the data-status edge). Section headings are ink plus a rule. That is the fix for the nine saturated lime bars the external review measured.
