Annotation key · Dashboard

  1. One primary action. "Open cockpit" is the only filled button in the top region. The page-head "New career" is the second, and only because a landing screen owes a way to start one; every other action is an outline or a link.
  2. Contradiction printed, not hidden. This screen reports turn 1 because stripValues() returns turnEntries->count(), while the cockpit reports turn 67 from nextTurnToPlay(). Both are labelled and the note names the defect. A wireframe that silently picked one would be the same class of error the audit filed against Energy.
  3. Absence keeps its tile. Energy and team rank say "not recorded" rather than dropping the row. The external prototype review's "drop the row" rule is applied to explanation paragraphs, not to a value the screen claims to report.
  4. Nav taxonomy, two levels. Ten destinations grouped as Play / My data / Library / System. The running sidebar is one flat list of ten, which breaches the "at or under eight" target recorded in AppLayout.vue:178; grouping fixes it without deleting a destination.
  5. Mobile is a different shape. Below 760px the sidebar becomes design-2.0 §41's bottom bar: Home / Career / Legacy / Deck / More.
  6. Accent discipline, measured. Three different roles were drawing on one accent before this pass: the current destination's fill, the provenance chip, and the recommendation pill. Each now has its own token. The status lime appears once (the "1 active career" pill), the action blue once (the primary), the risk red once (the data-status edge), and the brand accent once (the recommendation). The current destination wears the chrome's 10% tint (AppLayout.vue:239), and provenance wears ink weight rather than hue, so the accent means "this is the recommendation" and nothing else. Section headings are ink plus a rule. That is the fix for the nine saturated lime bars the external review measured.
  7. Von Restorff on the primary action. "Open cockpit" is the only filled button in the top region, so the page has exactly one accented element competing for the next click. Two filled actions would make the accent mean "a button" instead of "the button".
  8. Heuristic coverage. H8. One primary action and a dashboard of what changed, with the long tail behind links.
  9. Framework coverage. Tognazzini 10 on latency and Shneiderman 3 on proportional feedback. One filled action in the top region, so the page has exactly one thing to acknowledge when it answers, and the acknowledgment is the whole of the top region.
  11. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is at the head of the rail, where DESIGN.md §2.2 puts a control that belongs to a pane: the penalty for a distant control is exactly why the top-bar version was wrong. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
  12. The picture slots are drawings, and absence is a normal state. The app renders a mirrored card_portrait beside the career name at 64px and beside each veteran at 40px (ArtworkSlot.vue, DESIGN.md §4.7). A file the mirror does not hold renders nothing — no grey box, no placeholder glyph — and the row keeps its text. The dashed frame here marks a cell the picture would occupy, and the subject in it names the picture that belongs there.

Wireframe only. Values are the live dashboard payload read from http://127.0.0.1:8000/ on 2026-10-21: counts 71 / 1910 / 559, 7 veterans, verified 2026-09-27. No component, token, gate or test changed.
