Annotation key · Trainee profile

  1. A read screen says so. The lede tells a Trainer nothing here is edited, which stops the Paradox of the Active User from hunting for an edit control that does not exist.
  2. Aptitude and stat grade are kept apart in prose, not merged by colour. The running cockpit's TeamPanelBuilder stamps a locally invented grade band that config marks provisional (grade_banding.provisional => true). An aptitude letter from the catalog and a provisional stat grade must never share a label, and this screen says which one it is showing.
  3. Zeros print as +0%. The growth row is always five cells wide, matching the client's own render (UMAMUSUME_REFERENCE.md §1.3.5). A blank cell would read as "not recorded", which is a different fact.
  4. Absent data keeps its row. Base stats are not on this payload, so five rows state the absence and the note explains the 450 rule rather than deleting the block. This is the line between the repo's "absence prints with its reason" rule and the external review's "drop the row" rule: the row stays when the screen claims to report the value.
  5. Two or three actions at most. Back, a way to change the choice, and Continue. The change action is a full outline button rather than a bare link, because the whole point of this screen is deciding.
  6. Heuristic coverage. H10. The growth row and base stats are stated where the decision is made; nothing here requires reading a guide first, which is H10’s point that documentation is a fallback, not the path.
  7. Framework coverage. Norman on the conceptual model, and Information architecture 1 on objects. The trainee is a character with a growth row, a stat base and an identity, not a row in a form.
