Import

Bring in a historical career

Paste a run write-up or upload a file. The importer reads what it can, shows you what it found, and writes nothing until you confirm.

○ Nothing is written on this step. The importer's output is reviewed on the next screen, where every extracted field can be corrected before it becomes a run.

What the importer looks for

ScenarioOne of the four Global scenarios, by name.
Trainee and costumeName plus an optional [Costume] tag.
PositionA year, a month and a turn number.
StatsFive labelled figures, in any order.
Mood and EnergyOne of the five mood tiers; a figure or a band word.
Team blockUnity Cup only: name, motto, league, trainings, burst counts.

○ Anything the importer cannot find stays empty. It never fills a missing field with a default, which is why a partially read import is a normal outcome rather than an error.

Files you can upload

Markdown, plain text or the JSON export this app produces. A JSON export round-trips exactly; text is read heuristically and every field is shown for review.

Annotation key · Import

  1. Write nothing until confirm. The whole import is a preview step followed by a commit. Parsing into the database directly would make a bad read permanent and unreviewable.
  2. Absence is a normal result. A partially read import is expected and is not an error state. The importer states what it found rather than blocking on what it did not.
  3. The textarea is the primary control, set large. Pasting a run write-up is the common case and deserves more space than a filename picker.
  4. Format support is stated, not discovered. The card says which formats round-trip and which are heuristic, so a Trainer knows how much review to expect.
  5. Postel’s Law is this screen’s whole contract. Accept liberally — pasted text, Markdown or the app’s own JSON — and emit conservatively, in the client’s own enum labels. Anything the parser cannot find stays empty, because absence is a normal result and a default would be an invention.
  6. Heuristic coverage. H5. Nothing is written until the commit is confirmed, which is the check-before-commit half of error prevention.
  7. Framework coverage. Shneiderman 5 on error prevention and Gerhardt-Powals 8 on only what is needed. Nothing is written until the commit, and the screen asks only for what the parser could not find.
  9. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is in the top bar because the bar is the one row present at every width. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
