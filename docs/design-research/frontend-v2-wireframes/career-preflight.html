Annotation key · Preflight

  1. Peak-End Rule at the commit. The last screen before the run starts is the one that lists what will exist and what to expect. A confidence drop here costs the whole run, so the page ends with the commit and nothing else.
  2. One warning, stated once. The external review's "preflight single-row warnings, no duplicate Edit" is applied literally: one row, one link to the place the fix lives, no repeated copy.
  3. Product gaps are described as behaviour, not as build status. "Fans are not recorded on every turn, so a fan gate cannot be marked met until one is" replaces "not built", which is developer text in a user interface.
  4. The scenario's own asks are summarised from its entry — repetition, fan gates, Happy Meek, finale targets — rather than restated from memory. Where the scenario owns a fact, this screen points at it.
  5. Commit is the only filled action. Back is an outline. The run is not created until a turn is logged, so the screen promises nothing it does not do.
  6. Heuristic coverage. H1 + H5. Everything the run will contain is stated before the commit, and the one warning names its own fix instead of asking the Trainer to find it.
