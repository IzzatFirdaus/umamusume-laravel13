Annotation key · URA Finale cockpit

  1. A closed run has no advisor. AdvisorRail is v-if="isActive" in the running app, so a Completed run shows the complete-state sentence instead of a recommendation. That behaviour is correct and is reproduced here.
  2. The published-vs-observed cap caveat is kept. URA's published cap is a flat 1400; two client captures showed unequal ceilings on specific runs. A tool must not print those as "the URA cap", and this page prints the published row.
  3. The guide is a recommendation, not a gate. Printing the win alongside a short stamina figure is the most useful thing this screen can say.
  4. Goal-Gradient has to shrink to what a closed run can still claim. The finale is met, so the bar that drove the run is replaced by its record and the remaining obligation is the career-end gate. Keeping a live countdown on a finished run would be a progress cue that no longer means anything.
  5. Heuristic coverage. H1. A closed run states its outcome first, because the status that matters after completion is what was achieved.
  6. Framework coverage. Shneiderman 4 on closure. A closed run has no advisor, so the screen states the outcome and replaces the rail rather than leaving an empty region that reports nothing as if it were a status.
  8. The rail collapses, and the word never leaves the DOM. The app can collapse its global navigation to marks instead of words, and this set does the same (AppLayout.vue:191-233). A collapsed destination moves its label to sr-only and gains a title, so it keeps its accessible name; the active one keeps aria-current="page" and a left rule, so state never rides on colour alone. The control is at the head of the rail, where DESIGN.md §2.2 puts a control that belongs to a pane: the penalty for a distant control is exactly why the top-bar version was wrong. The choice is localStorage, not a Preference row, because Preference::KEYS is exactly theme and failure_estimate.
