### R3.1 OQ-3 fetch scheduler default — RESOLVED: manual-only, confirmed in code

`bootstrap/app.php:50-53` registers exactly one scheduled command:

```php
->withSchedule(function (Schedule $schedule): void {
    $schedule->command('independent-training:complete')->everyMinute();
});
```

A repo-wide search for `withSchedule|schedule->command|Schedule::` returns five hits, all accounted for: the two lines above and three mentions inside `tests/Feature/IndependentTrainingLifecycleTest.php` (which documents that `schedule:list`, not `Schedule::events()`, is the authoritative surface). **`uma:fetch` appears in no schedule registration.** The PRD's stated default is therefore not just policy but the shipped behaviour.

Ruling: **OQ-3 CLOSED — `uma:fetch` is manual-only by default, and that is deliberate.** No code change. Rate-limit behaviour of the chosen sources remains unobserved, which is the condition the PRD set for revisiting; the scheduler slot stays free. Adding a fetch schedule later means one `$schedule->command('uma:fetch')` line plus one test asserting `schedule:list` contains it.

### R3.2 OQ-6 artwork remainder — RESOLVED: skill icons out of scope, pick-screen model confirmed

**(a) Pre-run pick screen — native `<select>` content model.** No artwork change owed. The picker is a text control by design (an `<option>` cannot carry an image), and OQ-6's own wording records this as the placement answer, not a gap to close with images.

**(b) `skills.iconid` migration — OUT OF SCOPE, on measured grounds.** The field exists in the source data and in no table:

- `database/seeders/data/skills.609afe88.json` carries `iconid` on its rows (source field present).
- A search of `database/migrations/` for `icon` returns **0 matches** — no migration adds the column.
- `app/Http/Controllers/SkillController.php:43-44` documents the consequence in-tree, naming the register entry: *"the icon (`iconid` is on all 1,910 source rows and nothing stores it, G-SK-19)"*.

Ruling: skill icons are **declined for v3.0.0**, and the code already renders the absence honestly rather than faking a value (AGENTS.md §5: unrecorded value renders `N/A` with disclosure, never a default). Adding them later is one migration + one parser field + one render slot, and it is gated on the same governing question as G-SK-19: whether a skill icon is a surface this product wants. Recording the decline is the resolution; no migration is written for a feature the PRD has not asked to ship.
