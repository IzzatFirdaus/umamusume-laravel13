## What the Rosy Dreams doc comparison turned up

**The app matches the client exactly where the arithmetic lives, and diverges on labels and unrepresented systems.**

- All five **live stat values** match the doc's `§1.2` table to the digit: 607 / 577 / 549 / 736 / 397.
- All five **live caps** match to the digit: 1,325 / 1,322 / 1,368 / 1,308 / 1,800 — over the doc's `1300` floor.
  This is the strongest single result of the pass: the two-ceiling problem the dispatch named (scenario floor vs
  live cap) **is representable and is represented correctly** — the Cockpit prints the live cap, and the Scenario
  detail separately prints `Base 1200 + Bonus 100 = Cap 1300`. The two layers are both on screen; what is missing
  is only the *word* `cap` on the unrecorded run (BO-013). **BO-013 and the R6-04 two-ceiling problem are not the
  same fact**, and this pass separates them: R6-04's representation is correct, BO-013's noun is not.
- **Team name, motto and league placement** (`Blue Bloom`, `Dreaming Big`, `8`) match §1.8. The **`+30` bonus does
  not appear anywhere** → BO-015.
- **R6-08's spark scope** could **not** be arbitrated. The seeder imports no legacy selection, so the Cockpit
  correctly prints `No blue spark is recorded in this run's Legacy` and the Inheritance screen shows both parent
  slots open. There is no disagreement to measure, because there is no data. The doc's six-spark tree is
  unrepresented — and the seeder's own docblock says the omission is deliberate (EX-16).
- **R6-47's roster gap**: the doc's 20 members against the app's six deck slots is **not a rendering defect**. The
  deck screen faithfully renders what is stored, which is nothing. The seeder writes no deck (`deck_slots` has 0
  rows for run 14 by design). Recorded as EX-16, and I withdrew it as a finding after her docblock contradicted me.
- **The burst count is genuinely inconsistent** and is the one place the doc comparison produced a defect:
  `11 inside 10-12` beside `need 2 more` (BO-016), and `11` on the Cockpit vs `6` on the Scenario detail (BO-017).

So: not "nothing new" — but the new findings are label- and disclosure-level, not arithmetic-level.

## The one procedural thing worth flagging

Two seeding traps cost real time and would cost an owner more, because both fail **silently and green**:
`DB_DATABASE=… php artisan …` from this host's bash does not set the variable (seeders log `DONE`, rows: none), and
`php -S` must run with cwd=`public` or every request 500s on a missing `index.php`. Filed as EX-13; it belongs in
`KNOWN-ISSUES.md`.
