## Original Requirement
From `docs/[Rosy_Dreams]Rice_Shower_Unity-Cup.md` §1.3 and the Group A/B audit addendum of 2026-10-24:
- Record the facility banner name the training tile showed on a given turn
- Record the list (or join table) of support-card avatars the tile displayed
- Both are entered facts in the grain of `failure_rate` and `preview_gains`

**KI-124 finding**: "There is no column for the facility banner name and no column for the three support cards whose avatars the tile showed"

## Owner Question (Corrected)
**Exact question**: Should the owner add bounded observation fields for facility banner and training participant identities, with scope bounded to a selected training tile, a particular preview, or a recorded turn, and delegate schema selection (json column vs join table) to Backend without requiring the owner to choose unless a genuinely consequential architecture decision exceeds existing delegation?

**Option A**: Add bounded observation fields with schema delegation (Option A): Add `facility_banner` and `training_card_ids` (or equivalent model fields) to `turn_entries`, with scope bounded to a selected training tile, a particular preview, or a recorded turn — do not assume every tile contains exactly three participants. Backend determines the persistence architecture (json column vs join table); frontend populates the fields from the training tile UI; fullstack verifies integrated acceptance. Record the owner ruling with a dated travel note on FR-C-2 narrowing US-12's scope to the bounded observation model.

- **Evidence required**: Migration script (architecture: json column or join table per backend decision); model updates (backend); Cockpit read path update (frontend); test coverage; FR-C-2 travel note documenting the bounded scope
- **Development blocked**: Backend schema decision (json column vs join table); frontend UI recording; fullstack integrated acceptance test
- **Release relevance**: Optional per-turn detail; does not block core release

**Option B**: Decline A-0.12 — record as "will not add", keep the two facts unrecorded
- **Evidence required**: None needed; decline is the ruling
- **Development blocked**: None
- **Release relevance**: Maintains current state; no new functionality

**Option C**: Add only `facility_banner` and omit `training_card_ids` (or vice versa)
- **Evidence required**: PRD citation for the omitted item; backend decision on which field is essential
- **Development blocked**: Incomplete data capture; surface may need both fields; PRD citation required
- **Release relevance**: Partial feature; may create inconsistency

## Recommended Ruling (Corrected)
**Add bounded observation fields with schema delegation to Backend (Option A)**: Add `facility_banner` and `training_card_ids` (or equivalent model fields) to `turn_entries`, with scope bounded to a selected training tile, a particular preview, or a recorded turn — do not assume every tile contains exactly three participants. Backend determines the persistence architecture (json column vs join table); frontend populates the fields from the training tile UI; fullstack verifies integrated acceptance. Record the owner ruling with a dated travel note on FR-C-2 narrowing US-12's scope to the bounded observation model.
