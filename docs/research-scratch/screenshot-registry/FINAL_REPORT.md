## 1. What the subsystem is

A machine-readable, per-image research registry for the 1,159 original in-game screenshots in `docs/game-screenshots/`. It exists so a future agent can resume visual research across sessions without re-reading the entire corpus, and so visual inspection is reserved for images that actually need it.

The registry's contract is documented in `README.md`. The tool is a single Python script (`tools/screenshots.py`, 1,251 lines, 13 subcommands) with 14-assertion selftest (`tools/screenshots_selftest.py`). Batch selection is driven by a helper script (`tools/build_b002.py`) that picks one representative per distinct cluster size plus a time-spread of singletons.

Two identifiers per frame:
- `ref` — the capture timestamp (e.g. `2026-07-18 133731`). Human-facing key; what legacy notes reference.
- `sid` — first 12 hex of SHA-256. Content-derived; survives rename.

The two never replace each other: two files with matching stems but different bytes are different screenshots.

## 5. Key accomplishments

### 5.1. Registry integrity hardening
- **Problem:** Four concurrent `screenshots.py review` calls caused a write race on `inventory.jsonl.tmp`, corrupting 7 inventory records with concatenated JSON records.
- **Solution:** 
  - Replaced `write_jsonl` with OS-level file locking (using `msvcrt.locking` on Windows, `fcntl.flock` on POSIX) that is automatically released on process death.
  - Added `registry_lock` context manager to serialize the full read-modify-write transaction in `cmd_review`, `cmd_inventory`, `cmd_notes`, and `cmd_evidence`.
  - Added 3-phase regression test (sequential threads, concurrent threads, concurrent processes) to prevent regression.
- **Outcome:** No further corruption; all inventory mutations are now safe under concurrency.
