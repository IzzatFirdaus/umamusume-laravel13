## 5. Implementation details

### `resources/js/spa.ts` — navigation focus (accessibility)

Added `registerNavigationFocus()` called after `createInertiaApp(...).mount(el)`:

```ts
function registerNavigationFocus(): void {
    let previousComponent: string | null = null;
    router.on('navigate', (event) => {
        const { page } = event.detail;
        const changed = previousComponent !== null && previousComponent !== page.component;
        previousComponent = page.component;
        if (!changed) return;
        const errors = page.props.errors as Record<string, unknown> | undefined;
        if (errors !== undefined && Object.keys(errors).length > 0) return;
        void nextTick(() => {
            const heading = document.querySelector<HTMLElement>('main h1, h1');
            if (heading === null) return;
            heading.setAttribute('tabindex', '-1');
            heading.focus({ preventScroll: true });
        });
    });
}
```

- Imports added: `nextTick` from `vue`, `router` from `@inertiajs/vue3`.
- Two guards preserve existing focus behavior: same-page re-renders (filter/sort/search) leave the Trainer's input focused; validation-response pages focus their own `role="alert"`.
- Rationale: keyboard/screen-reader Trainers have no signal that the destination changed on a page change inside the SPA shell where `onMounted` never fires again. The wizard already solves this via `SetupLayout.vue:128-169`; this extends the same policy to persistent-shell pages.
